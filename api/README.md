# Публичный API прогноза

Java 21, Spring Boot 4, WebFlux. Прогноз лежит в памяти целиком (14 640 чисел),
API его выбирает и умножает на поправки — тяжёлых расчётов в запросе нет.

## Запуск

```sh
docker build -t tram-forecast-api .
docker run --rm -p 8080:8080 -e API_USER=dispatcher -e API_PASSWORD=<пароль> tram-forecast-api
```

Образ для жюри собирается под linux/amd64:

```sh
docker buildx build --platform linux/amd64 -t tram-forecast-api:amd64 --load .
```

Прогноз внутри образа — `/app/data/forecast.csv` в формате загрузки
на лидерборд (`route;date;hour;prediction`). Свой файл подставляется
переменной `FORECAST_FILE` или монтированием тома. Файл проверяется при старте:
неполная сетка, дубль ячейки, час вне 0—23 или отрицательный прогноз останавливают
запуск, и новая версия не выходит в работу, пока отвечает прежний контейнер.
Какая версия отвечает, видно в `/api/health` — поле `version`, начало SHA-256 файла.

Доли остановок — `/app/data/stop_shares.csv` и типы дней окна `/app/data/day_types.csv`
(`STOPS_FILE`, `STOPS_DAYS`), их считает `python -m tramflow.stops`. Маршрута нет в долях —
`/api/stops` отвечает 404 с причиной: направление рейсов не определилось или истории нет.
Сумма посадок по остановкам за час равна прогнозу маршрута до округления. Час, в который в октябре посадок не было (ночь выходного), берёт доли ближайшего часа того же типа дня — это видно в поле `sharesFrom`; посадки часов совсем без долей отдаются в `unallocated`, а не теряются.

Пользователей два, у каждого своя роль. Диспетчер (`API_USER`, `API_PASSWORD`)
читает прогноз и экран. Сервис приёма (`INGEST_USER`, `INGEST_PASSWORD`) только
загружает валидации в `POST /api/ingest` — прочее ему закрыто, а диспетчеру
закрыт приём. Значений по умолчанию у паролей нет: без `API_PASSWORD` и `INGEST_PASSWORD`
сервис не стартует. При сдаче логины и пароли идут отдельным файлом. Без авторизации
открыты только `/api/health` и `/actuator/health`.

Перебор паролей ограничен: адрес с более чем 20 неверными паролями за минуту
получает 429 на 5 минут, а новых проверок bcrypt не больше 8 в секунду на весь
сервис. Уже проверенные пары идут мимо лимита. Пороги — `GUARD_FAILS_PER_IP`,
`GUARD_BLOCK_MINUTES`, `GUARD_BCRYPT_PER_SECOND`; за балансировщиком —
`FORWARD_HEADERS=framework`, чтобы адрес клиента брался из `X-Forwarded-For`.

## Методы

| Метод | Что отдаёт |
|---|---|
| `GET /api/health` | окно прогноза, число маршрутов и точек |
| `GET /api/routes` | маршруты с суммой за окно и часом суточного пика |
| `GET /api/forecast` | срез прогноза: час, день или месяц |
| `GET /api/forecast.csv` | тот же срез выгрузкой |
| `GET /api/risk` | часы, где прогноз выше заданной провозной способности |
| `GET`, `POST /api/nowcast` | остаток дня маршрута, пересчитанный по факту прошедших часов |
| `POST /api/ingest` | приём валидаций выгрузкой в формате `train.csv` |
| `GET /api/fact` | принятый факт маршрута за день: посадки по часам и время последней валидации |
| `GET /api/stops` | посадки по остановкам: прогноз маршрута за час × доля остановки; `route`, `date`, необязательный `hour` (без него — сумма за день); две стороны движения отдельно, поле `confidence` — насколько определено направление рейсов |
| `GET /api/stops/routes` | для каких маршрутов есть посадки по остановкам и уверенность в направлении |
| `POST /api/telemetry` | приём отметок ГЛОНАСС от навигационной платформы |
| `GET /api/vehicles` | вагоны на карте: последнее положение, скорость, курс и давность связи |

Параметры `/api/forecast`, `/api/forecast.csv` и `/api/risk`:

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `routes` | все десять | список номеров через запятую: `7,50` |
| `from`, `to` | всё окно | границы периода, `ГГГГ-ММ-ДД` |
| `granularity` | `hour` | `hour`, `day` или `month`; день равен сумме часов, месяц — сумме дней |
| `weather` | `1.0` | поправка на погоду |
| `event` | `1.0` | поправка на событие |
| `season` | `1.0` | поправка на сезон |
| `capacity` | — | для `/api/risk`: провозная способность в посадках за час |

Поправки перемножаются и применяются к часам до агрегации, поэтому сумма дня
всегда равна сумме своих часов. Каждая из них — индекс по маршруту или городу,
а не расчёт по остановкам: на этом уровне детализации данные валидаций
привязки к остановке не дают.

```sh
curl -u dispatcher:<пароль> 'http://localhost:8080/api/forecast?routes=7,50&from=2025-12-24&to=2025-12-24'
curl -u dispatcher:<пароль> 'http://localhost:8080/api/forecast?granularity=month&weather=0.98'
curl -u dispatcher:<пароль> 'http://localhost:8080/api/risk?capacity=1500&from=2025-12-31&to=2025-12-31'
```

### Пересчёт по факту дня

Прогноз на два месяца вперёд не знает, каким выйдет конкретный день, а диспетчер
к 9—11 утра уже видит валидации. Отношение факта к прогнозу за прошедшие часы
переносится на оставшиеся часы дня. Октябрь 2025, остаток дня по девяти маршрутам:
по факту до 9:00 — 0,904 против 0,900 без пересчёта, до 11:00 — 0,906 против 0,898.
Выпуск вагонов и погода того же не дают: на истории они дневной остаток не объясняют.

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `route`, `date` | — | маршрут и день |
| `fact` | — | посадки за прошедшие часы: `6:120,7:340,8:410`; в POST — JSON `{"6": 120, "7": 340}`. Без `fact` берётся принятый через `/api/ingest` |
| `until` | час последней валидации | только без `fact`: факт берётся за часы до `until`; без него последний час с валидациями считается незакрытым |
| `trust` | `0.5` | степень при отношении: `1` — перенос целиком, `0.5` — корень из него; при `1` в 7—9 часов хуже, чем без пересчёта |
| `minHours` | `2` | меньше часов факта с прогнозом от 50 посадок — пересчёт не применяется, `applied: false` |

Отношение считается только по часам, где прогноз от 50 посадок, и только если их
сумма не меньше 300: иначе одна лишняя валидация в 5—6 утра меняет весь день.
Множитель ограничен пределами 0,8—1,25, `usedHours` — сколько часов вошло в расчёт.
Час, где факт меньше пятой части прогноза, — провал данных: обрыв связи с валидаторами
или сбой выгрузки, а не пустой трамвай. В отношение он не входит и возвращается
в `gapHours`; без этого один такой час уводил весь остаток дня к нижней границе. Ответ — часы с первого невиденного: `prediction` после пересчёта,
`plain` — до него, `factor` — множитель.

```sh
curl -u dispatcher:<пароль> 'http://localhost:8080/api/nowcast?route=7&date=2025-12-24&fact=6:410,7:1290,8:1980'
curl -u dispatcher:<пароль> -H 'Content-Type: application/json' -d '{"route":7,"date":"2025-12-24","fact":{"6":410,"7":1290,"8":1980}}' http://localhost:8080/api/nowcast
```

## Приём валидаций

Выгрузка в формате `train.csv` (разделитель `;`, первая строка — заголовок) отправляется
телом запроса и читается потоком: файл в гигабайты в память не ложится. Нужны колонки
`tran_date_time`, `validation_result` и `ngpt_route`, порядок любой. Посадкой считается
`validation_result = 1`; битые строки отклоняются с номером строки и причиной, остальная
выгрузка принимается.

`X-Batch-Id` — номер пачки у отправителя. Пачку с уже принятым номером второй раз
не считаем: после обрыва связи источник может прислать её повторно. Посадки пачки
копятся отдельно и попадают в факт только после того, как выгрузка дочитана без ошибки:
оборванная посередине пачка не оставляет в факте ничего, и её повтор ничего не удваивает.
Строки чужих маршрутов (которых нет в прогнозе) пропускаются и считаются в `foreign`,
даты дальше года от окна прогноза — ошибка строки.

Принятая пачка дописывается в журнал `FACT_JOURNAL` (в образе — `/app/state/fact.log`,
в `compose.yml` это том `tramflow-state`): после перезапуска копия читает журнал и
продолжает с того же факта, номера принятых пачек тоже восстанавливаются. Пачка попадает
в журнал только после того, как целиком легла в память, запись с `dsync`. Пустой
`FACT_JOURNAL` выключает журнал; недоступный путь не роняет сервис, факт тогда живёт
до перезапуска. Копии на одном томе друг у друга факт не читают — общее хранилище
для нескольких копий остаётся задачей пилота.

```sh
curl -u ingest:<пароль> -H 'Content-Type: text/csv' -H 'X-Batch-Id: 2025-12-24-08' \
  --data-binary @batch.csv http://localhost:8080/api/ingest
unzip -p dataset.zip test.csv | curl -u ingest:<пароль> -T - -X POST \
  -H 'Content-Type: text/csv' http://localhost:8080/api/ingest
curl -u dispatcher:<пароль> 'http://localhost:8080/api/nowcast?route=7&date=2025-12-24&until=12'
```

Ответ — строк, посадок, не посадок, битых, секунд и строк в секунду. `test.csv` целиком,
13,4 млн строк, принимается за 13 секунд. Разбор идёт в одном отдельном потоке, поэтому
приём не отнимает у экрана больше одного ядра.

## Координаты ГЛОНАСС

Навигационная платформа шлёт пачку отметок CSV, строка на отметку; порядок колонок любой,
`route`, `speed` и `course` необязательны. Время — ISO-8601 или миллисекунды от 1970 года.
Приём — той же ролью, что и валидации.

```sh
printf 'board;route;time;lat;lon;speed;course\n31055;25;2026-09-27T09:15:02Z;55.7801;37.6012;18.5;94\n' \
  | curl -u ingest:<пароль> -H 'Content-Type: text/csv' --data-binary @- http://localhost:8080/api/telemetry
curl -u dispatcher:<пароль> 'http://localhost:8080/api/vehicles?route=25'
```

Хранится только последнее положение вагона: история точек — дело навигационной платформы.
До карты отметка проходит проверки, и отброшенные считаются по причинам — так видно,
что шлёт неисправный терминал:

| Причина | Когда |
|---|---|
| `outside` | координаты вне Москвы — чаще всего нули от сбоя приёмника |
| `speed` | скорость больше 80 км/ч |
| `future` | время отметки больше чем на минуту впереди часов сервиса |
| `duplicate` | та же отметка ещё раз |
| `old` | отметка старше той, что уже на карте: опоздавшая не двигает вагон назад |
| `jump` | от прежнего места быстрее 150 км/ч — скачок от переотражения сигнала среди домов |
| `overflow` | вагонов в памяти уже 20 000 |

Если две отметки подряд согласны друг с другом, но далеки от прежнего места, вагон
перепривязывается ко второй: скачком было прежнее положение, и иначе вагон застрял бы.
Вагон без отметок дольше `TELEMETRY_STALE_SECONDS` (по умолчанию 120 секунд) в ответе
помечен `stale`, а на экране — «нет связи».

Экран «Живой день», открытый из сервиса, берёт вагоны отсюда раз в пять секунд;
без сервиса (`npm run dev`) показывает вагоны, восстановленные по валидациям.
