# Дашборд диспетчера — как устроен фронт и как его менять

Код лежит в `web/`; команды ниже выполняются из этой папки.

Экран диспетчера: React 19, Gravity UI, MapLibre, Vite. Сервера нет —
данные лежат в `public/data/` и собираются скриптом из меток организаторов
и попыток модели. Всё, что видно на экране, считается в браузере из этих
файлов и настроек.

Экран в три колонки. Слева узкая колонка разделов диспетчера: сетка, таблица,
карта, месяц; внизу — живой день, имитация и отчёты. Настройки, файлы
и клавиши — в меню «…» шапки; год — страница «Отчётов». Площадка выпуска выбирается в строке команд.
В имитации шапка держит управление прогоном: горизонт, режим входов,
длительность и «Пуск» у меню «…». На телефоне имитация и отчёты — в меню «…».

```sh
npm install
npm run dev            # http://127.0.0.1:5190, правки подхватываются сами
npm run build          # dist/ — статика, отдаётся любым сервером
npx tsc -b             # проверка типов без сборки
```

Пересобрать данные (нужны `data/raw`, `data/external`, `artifacts/submissions`):

```sh
.venv/bin/python web/scripts/fetch_mos_stops.py   # из корня; остановки с data.mos.ru, ключ MOS_API_KEY в .env
.venv/bin/python web/scripts/mock_data.py         # web/public/data/*.json
.venv/bin/python web/scripts/schedule_data.py     # рейсы по расписанию и выпуск → schedule.json
.venv/bin/python -m tramflow.horizons              # три модели по горизонтам → horizons.json, около 7 минут
```

`schedule.json` необязателен: без него рейсы в час считаются по интервалам из настроек.

`public/data/` и `public/assets/` в git не входят: первое собирается,
второе (воркер MapLibre) копируется хуками `predev`/`prebuild`.

данные → расчёт → состояние → экран. Ниже слой не знает о слое выше.

## Как данные попадают на экран

```
labels/*.csv, submissions/*.csv, справочники, погода, календарь
        │  scripts/mock_data.py
        ▼
public/data/{routes,series,models,history,context}.json
        │  data.ts: loadDataset()
        ▼
store.ds ──┐
settings ──┼─► Ctx (useCtx) ──► model.ts: routeDay(ctx, route, day)
adj      ──┤                         │ fc, fact, load[], risk[], level
model    ──┘                         ▼
                              компоненты: список, карта, панель, метрики
```

`Ctx` — всё, от чего зависит расчёт: данные, настройки, поправки,
выбранная попытка, подменённый день со стенда, час смены. Компонент получает `ctx`
пропсом и зовёт `routeDay`; своих формул в компонентах нет.

Окно экрана — 122 дня с 1 сентября по 31 декабря 2025 (`START`, `DAYS`
в `data.ts`). Первые 61 день (`FACT_DAYS`) — факт и прогноз-бэктест,
дальше — прогноз попытки. День везде — индекс в этом окне, а не дата;
`isoOf`, `idxOf`, `dowOf`, `ruDay` переводят туда и обратно.

Что лежит в `public/data`:

| Файл | Содержимое |
|---|---|
| `routes.json` | маршруты: имя, дата версии, остановки по порядку, откуда взята трасса (`org` — справочник, `mos` — открытые данные) |
| `series.json` | сентябрь—октябрь: факт и бэктест по маршрутам `[день][час]`; интервал — множители 10 и 90 % по дню недели и часу |
| `models.json` | попытки (`log`), их прогнозы ноября—декабря (`nd`), сравнение решений на октябре (`compare`, `oct`) |
| `horizons.json` | три модели на одинаковых входах: счёт по горизонтам и прогон для имитации, два режима — без погоды и с фактической погодой (`tramflow.horizons`) |
| `history.json` | посадки по дням с января — для годового экрана |
| `context.json` | производственный календарь и погода по дням: температура, дождь, снег |
| `network.json` | трамвайные маршруты Москвы вне задания: трассы для фонового слоя карты; собирает `scripts/network_data.py`, при отсутствии файла слоя нет |
| `stops.json` | доли посадок по остановкам [час][направление][остановка] для будней и выходных и тип дня окна; собирает `python -m tramflow.stops`; только маршруты с определённым направлением рейсов, при отсутствии файла схема линии показывает одни остановки |

## Правила, которые держат экран

**Число, от которого зависит расчёт, лежит в `settings.ts` с источником.**
Порог, вместимость, интервалы, ширина интервала прогноза — всё в
`DEFAULTS`, и у каждого в `SCHEMA` подсказка, откуда число. Форма
настроек строится из схемы сама, второго списка полей нет. Хардкод
допустим только там, где значение — наблюдение по данным, и тогда оно
названо константой рядом с замером (`RAIN_MM`, `RAIN_EFFECT` в `model.ts`).

**Цвет — только через переменные `--b-*` в `theme.css`.** В компонентах
и `index.css` нет литеральных цветов, кроме белого набора на знаке.
Красный — знак (`--b-brand`) и превышение порога (`--b-over`, с ним
`--b-danger`); синий (`--b-accent`) — маршрут и главное действие;
шкала загрузки — `--b-l0`…`--b-l4`. Gravity получает те же цвета через
`--g-*` в конце файла. Тема хранится в `data-theme` на `<html>`.

**Загрузка — оценка, и об этом сказано на экране.** Валидация видит вход,
поэтому загрузка = посадки пикового направления ÷ (рейсы в час в одну сторону
× вагоны × вместимость × пассажиросмена) (`capacityHour`, `loadPct`
в `settings.ts`). Загрузка есть только у часа маршрута: остановки в валидациях
нет, и схема линии и карта загрузку по остановкам не показывают. Пометку
«оценка» без настоящих данных не убирают.

**Сумма сходится.** Прогноз дня — сумма часов, месяца — сумма дней.
Метрика «сумма по уровням» в полосе внизу это проверяет; если после
правки она показывает «расходится», правка сломала агрегацию.

**Без сети экран остаётся рабочим.** Подложка карты приходит с тайлов
OSM; не пришла — линии и всё остальное на месте, на карте подпись.
У жюри интернета может не быть; для сдачи подложку нужно положить
в образ файлом тайлов.

## Как сделать типовую правку

### Добавить настройку

1. Значение в `DEFAULTS` (`settings.ts`).
2. Поле в нужной группе `SCHEMA`: `key`, `label`, `type` (`number`,
   `choice`, `bool`), единица, границы, `hint` с источником числа.
   Группа с `tech: true` уходит на вкладку «Модель».
   Группа `network` — показ сети вне задания и её поправка.
3. Прочитать в расчёте: `ctx.s.<key>` (`model.ts` или `settings.ts`).

Форма, «вернуть», «сбросить всё» и память в `localStorage` работают сами.

### Добавить поправку к прогнозу (ползунок в панели)

1. Поле в `Adjust` и значение в `ADJUST_DEFAULT` (`model.ts`).
2. Множитель в `factors()` — он же попадёт в «Почему так» с подписью.
3. Шаблон в `WindowCard.tsx`: имя в `TEMPLATES`, включение и выключение
   в `templateToggle`, ползунок в `Templates` — `Slider` из Gravity и
   `setAdj({ … })`. Шаблон сам попадёт в строку команд ⌘K.

### Добавить внешний фактор (вкладка «Факторы»)

Группа `factors` в `settings.ts`: тумблер (`bool`) плюс число рядом, в подсказке —
чем измерена величина (история, попытка на лидерборде, гипотеза) и что дала.
Гипотезы по умолчанию выключены. Расчёт читает поля в `factors()` в `model.ts`;
множители, уже зашитые в предрасчёт лучшей попытки (уровень маршрута 5, вечер
31 декабря), считаются отклонением от зашитого. Признаки по дням — `public/data/factors.json`,
его пишет `data/external/build_features.py`.

### Добавить метрику в полосу внизу

`MetricsBar.tsx`: посчитать из `sc` (день сети из `useScreen`: `days`,
`wins`, `after`) и добавить `<div><b>число</b>подпись</div>`. Классы
`ok`/`over` у числа красят его зелёным или малиновым.

### Подключить настоящий API

Заменить `loadDataset()` в `data.ts` на запросы к сервису, сохранив
форму `Dataset`. Компоненты и расчёт про источник не знают. Если
прогноз считает сервер, `forecastDay` в `model.ts` становится выборкой
из ответа, а поправки — либо остаются умножением в браузере, либо
уезжают в параметры запроса.

Сервис уже отвечает теми же срезами: `GET /api/forecast` с параметрами
`routes`, `from`, `to`, `granularity` и поправками `weather`, `event`,
`season` (см. `api/README.md`). Базовая авторизация — заголовком.

### Добавить модель или горизонт в имитацию

1. Модель — ключ в `MODELS` (`tramflow/horizons.py`) и её прогноз в `run()`;
   входы берутся из `Inputs.frame()`, одинаковые для всех.
2. Горизонт — число в `SHORT` или `LONG` там же; пересобрать `horizons.json`.
3. На экране — строка в `MODELS` (`SimView.tsx`) с цветом `--b-m-*` из `theme.css`
   и строка в `HORIZONS` (`analytics/ModelsPage.tsx`).

### Добавить маршрут или сменить трассу

Маршруты берутся из `routes.json`. Трасса из справочника организаторов
предпочтительнее открытых данных: `mock_data.py` берёт справочник,
если он есть, иначе набор 752 с data.mos.ru, где порядок остановок
восстанавливается по близости. Список маршрутов для настроек —
`ROUTE_IDS` в `settings.ts`.

### Поменять окно дат

`START`, `DAYS`, `FACT_DAYS` в `data.ts` и матрицы в `mock_data.py`
(`to_matrix`, `grid`). День по умолчанию — `day` в `store.ts`.

## Вёрстка

Ступеней три: до 1100 px панель уже, до 760 — разделы уходят полосой вниз,
панель и главная область идут одна под другой (`lib/media.ts`, медиазапросы
в конце `index.css`).
Классы узлов с префиксом `b-`; всё, что умеет Gravity (кнопки, меню,
выпадающие списки, переключатели, ползунки), берётся у него, свои
только те узлы, которых у него нет. Tailwind подключён, но используется
для мелкой раскладки (`flex`, `gap`), а не для цветов и типографики.

Значки — `lib/icons.tsx`, поле 16×16, контур штрихом, краска
`currentColor`. Значок с текстом в кнопке оборачивают в `b-btn`,
иначе он съезжает с оси строки. Значок без текста в кнопке Gravity
ставят прямо в неё: Gravity считает своим знаком только `Icon` и кладёт
наш SVG в текст кнопки, растянутый на всю высоту, — центрует его одно
правило `.g-button__text:has(...)` в начале `index.css`.

## Экран дня: окна, приоритеты, решение

Окно риска — часы подряд, в которые загрузка маршрута не ниже порога
внимания (`model.ts`, `riskWindows`). Приоритет по пику окна: первый —
от `prio_high_pct`, второй — от порога перегрузки, третий — от порога
внимания. Причины окна (`causesOf`): поправки, праздник, «выше обычного
вторника», пик. Окна одной причины сворачиваются в одну строку списка,
когда их три и больше.

Рекомендация считается в рейсах в час (`tripsNeeded`): сколько добавить,
чтобы каждый час окна встал не выше `target_pct`. В вагонах считать
нельзя — сколько их на линии, в данных задания не видно. Принятое решение
пересчитывает загрузку окна во всех панелях и остаётся в списке с отметкой;
отменяется из уведомления или `⌘Z` в течение восьми секунд.

По умолчанию сетка показывает только окна риска, штатное приглушено;
клавиша E показывает всю сеть. Час смены — `now` в `store.ts`, меняется
в шапке; раньше него часы приглушены, окна считаются с него.

## Пересчёт остатка дня по факту

В дни с фактом (сентябрь—октябрь и день со стенда) прогноз с часа смены
умножается на отношение факта к прогнозу за прошедшие часы — `nowcastDay`
в `model.ts`. `routeDay` отдаёт и `fc` после пересчёта, и `plain` до него;
в причинах окна пересчёт виден строкой «По факту до 11:00», в ленте чисел —
точность остатка дня с ним и без него и кнопка, которая его выключает.
Настройки — группа «Пересчёт по факту дня»: порог часов факта и доверие.

Измерено на октябре 2025: факт до 9:00 даёт +0,8 пп точности остатка дня,
до 11:00 — +1,0 пп. Фактический выпуск вагонов и погода дневной остаток
не объясняют (R² выпуска 0,02), поэтому входом пересчёта служит только факт.
Сервис отдаёт то же самое методом `/api/nowcast` (см. `api/README.md`).

У каждого раздела свой путь: `/` сетка, `/table`, `/map`, `/month`, `/live`, `/sim`,
`/reports/<страница>`. Переход меняет путь без перезагрузки (`lib/router.ts`), «назад»
и «вперёд» браузера возвращают раздел, прямая ссылка открывает его сразу: сервис отдаёт
на эти пути `index.html` (`api/…/ScreenRoutes.java`). Старые ссылки `?view=table` и `/year`
переводятся на новые пути. Остальное состояние — параметрами: `?mode=all`, `?detail=map`,
`?palette=1`, `?keys=1`, `?tpl=closure` (шаблон при открытии), `?sel=17-15` (маршрут и час),
`?now=9`, `?day=2025-10-14`, `?theme=dark`; у имитации — `?hz=7d&mode_in=events`.

Клавиши ловятся по физической клавише (`e.code`), поэтому одинаково работают на Mac
и Windows, в латинской и русской раскладке; модификатор — ⌘ на Mac, Ctrl на Windows.

## Проверка перед коммитом

```sh
npx tsc -b && npx vite build
```

Дальше глазами: три горизонта, обе темы (меню «Стенд» → тема), сетка и
таблица, схема и карта, принять и отменить решение,
настройки → «Пересчитать», сравнение, стенд → «Прожить день» →
«Открыть день на экране» → стрелка дня снимает эмуляцию. В полосе
внизу «сумма по уровням» должна сходиться. В консоли браузера —
без ошибок.

В dev-сборке состояние доступно в консоли как `tf`:
`tf.getState().set({ day: 70, route: '12', horizon: 'month' })`.
